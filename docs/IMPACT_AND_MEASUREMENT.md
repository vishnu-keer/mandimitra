# Impact and measurement

No impact has been measured. This document defines what would count as
impact, how it would be measured, and what would show the product does not
help. No farmer interviews, user counts, savings or income effects are
claimed anywhere in this project.

## Intended outcomes

| # | Outcome | Indicator | How measured | Target for a first study |
|---|---|---|---|---|
| O1 | Users read the forecast correctly | % who correctly say whether the forecast is for today or for a past date | Task-based interview, 5–10 participants | ≥ 80% correct |
| O2 | Users understand the reference | % who can explain "same as today" in their own words after one view | Same session | ≥ 70% |
| O3 | Users notice uncertainty and staleness | % who mention the historical-data warning or the missing range unprompted | Think-aloud | ≥ 50% |
| O4 | The tool would change a decision | Self-reported: which screen, which decision, in what direction | Semi-structured questions | Qualitative; report all answers |
| O5 | No harmful over-trust | % who say they would act on the forecast alone | Same session | Report as a risk indicator; lower is better |
| O6 | Accuracy holds prospectively | Test RMSE/MAE vs Naive on prices published after each forecast | Automated, once current data is connected | Report monthly; no target — measure |

## Counter-indicators (what would show it does not help)

- Participants misread the date the forecast applies to.
- Participants treat the forecast as advice despite the notice.
- Prospective scoring shows the selected model worse than Naive over months.

## What we will not do

Estimate rupee savings or income gains without a controlled design; report
user counts as impact; quote individual participants by name.

## Reporting

Publish anonymised findings in the repository (`docs/USER_RESEARCH_FINDINGS.md`,
created only after the study), including results that are unfavourable.
